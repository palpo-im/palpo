## 运维与性能待办

### M01 · P2 · 完整运行指标与故障恢复演练

在 readiness 的 worker 状态和连接池快照之外，补充持久队列 pending/active/retry 数、最老年龄、worker 心跳新鲜度与恢复耗时、DB pool wait 时长、联邦 permit wait 及出站错误分布。现有队列 schema 不记录创建时间，应先设计兼容迁移与观测开销，不能用序号冒充年龄。

验收：可复现的 DB 短断连、慢/故障目的地、队列积压及进程重启演练，证明指标和告警随故障变化，恢复时间与持久请求数可核对。

### P02 · P2 · 统一发送调度中的串行查询

`sending/guard.rs` 的设备列表和 receipt 路径按房间/用户串行查询。先测每批 SQL 次数、连接等待及调度停顿，再改批量 join/增量索引；覆盖单个慢目的地不长期阻塞健康目的地的公平性。尚无压测证明这是当前最大瓶颈。

### P03 · P2 · PDU 批内重复读取

`sending.rs` 的逐 PDU 读取和转换可评估批量读 JSON、按房间复用 room version。验收需要相同房间版本/事件签名语义及实际查询次数、尾延迟对比。

### P04 · P2 · 公开目录工作量与分页大小无关

`directory.rs` 仍先读取所有公开房间属性再排序分页。评估目录投影、批量读取及稳定游标；保留房间类型、网络过滤、计数和双向分页语义。并发目录变化的快照语义需要独立设计。

性能实验固定机器、配置、数据规模和源码/binary 摘要；覆盖小/大房间、多设备、共享房间数递增、慢联邦、突发 to-device、预览失败洪峰和 DB 短断连。记录吞吐、p50/p95/p99、event-loop lag、SQL 时间/次数、pool/permit wait、队列年龄、RSS、CPU 和恢复时间；测量后再定数值 SLO。

## 架构与协议验证待办

### A01 · P3 · 嵌入与可重载生命周期

配置、DB pools 和 workers 仍主要是进程全局状态；`MatrixServer` 明示每进程单实例。若要支持多个实例或可重载宿主，逐步引入持有 task handle 和 cancellation 的 service context，并证明关闭、重试初始化及资源回收。此项需要先明确兼容范围，避免一次重构全部全局状态。

### A02 · P3 · 大模块共享策略与死代码整理

sync_v5、membership/invite、sync_v3、OIDC 同时承担协议、DB 和业务策略。按具体重复不变量逐步抽取可见性、游标和投递确认；识别无调用旧安全实现并删除或标注。模块行数本身不是代码质量缺陷，抽取需保留真实 HTTP 回归。

### T01 · P2 · 真实 SDK 端到端加密与恢复

补真实 SDK 的加密/解密、设备验证、cross-signing、备份恢复和重新跟踪流程；转发 opaque encrypted PDU 不代表端到端流程成功。补 v5 HTTP 层设备变更对照，而不只比较 service 响应。

### T02 · P2 · 事件授权与 state resolution 差分

覆盖分歧 DAG、多房间版本、rejected/soft-failed、缺失前驱恢复，并与独立参考实现对照。当前单元测试和部分联邦互通不能代替完整差分证明。

### T03 · P2 · notary 信任边界专项审计

独立核查 notary 返回值身份、签名信任、缓存和轮换策略，覆盖恶意或不一致 peer；尚未确认具体新增漏洞。

### T04 · P2 · 存储、备份与恢复

补真实 S3、流中断、对象存储失败、跨主机网络分区、进程强杀及备份恢复演练，核对媒体/队列/数据库一致性与恢复步骤。

### T05 · P2 · 版本化能力与测试映射

为公开声明逐项记录 spec revision、feature 组合、真实 HTTP 用例及限制。第三方身份邀请仍返回 `M_UNRECOGNIZED`，`3pid/onbind` 的挂载方法应在实现时对照规范；第三方网络目录发布仍未实现。可选 MSC、Spaces/成员拓扑和权限组合分别列出，不用历史测试通过率概括所有能力。

每项提交应包含最小复现或测量基线、实现不变量、对应回归、验证边界，以及必要的兼容/迁移说明。只把具备对应证据的工作记为完成。
