# MSC4560 protocol models

Issue [#577](https://github.com/palpo-im/palpo/issues/577) tracks the complete
standalone stripped-state query feature. The `palpo-core/unstable-msc4560` Cargo
feature currently provides wire models and explicit request validation only.
The server has no MSC4560 routes or runtime enablement, and `/versions` does not
advertise it.

The models follow the [current proposal](https://github.com/matrix-org/matrix-spec-proposals/pull/4560),
reviewed on 2026-11-16, with
[Ruma's implementation](https://github.com/ruma/ruma/commit/19e6bf50dcc133d9becb1830e335e73e8f3f3c66)
as a reference:

- Client POST:
  `/_matrix/client/unstable/org.continuwuity.msc4560.stripped_state/{room_id_or_alias}`.
  The path accepts a room ID or alias; repeated `via` query entries are optional.
- Federation POST:
  `/_matrix/federation/unstable/org.continuwuity.msc4560.stripped_state/{room_id}`.
  The path accepts a room ID only.
- Both JSON bodies default to an empty `state` set and
  `num_joined_members: false`. An empty selection and count-only selection are
  valid. Requested types select every state key of those types.
- The shared allowlist contains exactly eleven types, including `m.space.child`
  and `m.space.parent`. `StrippedStateMsc4560ReqBody::validate` returns
  `M_INVALID_PARAM` for forbidden or unknown types.
- Client argument validation counts the original `via` vector before
  deduplication. More than 32 entries returns `M_TOO_LARGE`, as required by the
  proposal (Ruma's cited source comment says `M_INVALID_PARAM`).
- Responses always carry a `state` array. The member count is optional and zero
  is meaningful. Only the client response requires the supplying server's `via`.
- `FeatureFlag::Msc4560` identifies a peer's advertised capability. Defining this
  enum variant does not advertise local support.

Future server work must validate both arguments and body before any alias
resolution/network lookup, then implement the proposal's visibility rules.
The current proposal permits anonymous federation queries; Ruma's cited model
requires signatures. An eventual route must verify supplied credentials, apply
server ACLs and membership rules to signed callers, and evaluate unsigned
callers as anonymous. Private-room state and counts require authorization even
for empty/count-only selections.

`RawJson<AnyStrippedStateEvent>` preserves wire JSON. It does not remove unknown
fields from a remote response or authorize access. A federation proxy must
validate requested event types and reconstruct only `type`, `state_key`,
`sender` and `content`, removing full-PDU metadata before responding. Server
work also includes resident-room precedence, bounded alias/via lookup, network
and response-size limits, rate limiting, opt-in configuration and end-to-end
visibility/federation tests. Keep #577 open until those requirements are met.
